The dependency flow

Observe → Model → Estimate → Learn → Represent → Fuse → Deploy → Validate

No stage repairs an invalid upstream contract for free.

  1. 01

    Observe

    Sensors convert light, range, motion, and time into measurements. Ask what was sampled, when it was sampled, and what the device changed.

    Contract: units, dynamic range, noise, exposure, timestamp, field of view.

  2. 02

    Model

    A physical and geometric model relates the scene to the observation: projection, distortion, illumination, rigid motion, or sensor response.

    Question: which variables are observable, and under what scene or motion conditions?

  3. 03

    Estimate

    Inference recovers latent state from imperfect evidence using optimization, probability, robust losses, and temporal filtering.

    Output: a value plus residuals, uncertainty, conditioning, and failure status.

  4. 04

    Learn

    Data supplies priors that hand-written models cannot express. The objective, sampling process, labels, and augmentations define what is learned.

    Risk: a model can fit the benchmark while learning the wrong invariance.

  5. 05

    Represent

    Choose the state passed downstream: pixels, features, boxes, tracks, depth, point clouds, BEV grids, occupancy, or embeddings.

    Trade-off: every representation makes some queries easy by discarding other information.

  6. 06

    Fuse

    Combine cameras, LiDAR, radar, IMU, maps, language, and history only after aligning frames, time, semantics, and uncertainty.

    Test: missing, stale, contradictory, and miscalibrated inputs.

  7. 07

    Deploy

    Accuracy meets latency, memory, power, availability, privacy, monitoring, and rollback. The runtime is part of the model.

    Evidence: correctness and performance on target hardware, not a notebook average.

  8. 08

    Validate

    Translate ambiguity into a testable plan, define interfaces and review gates, make trade-offs legible, and specify degraded behavior.

    Result: assumptions fail loudly and the next experiment is clear.

One-scene trace

A distant pedestrian at dusk

The camera observes a low-signal crop; the projection model connects pixels to rays; a detector estimates class and box; learned features supply appearance priors; a track represents temporal state; radar and camera evidence are fused; deployment determines whether the result arrives before the planner deadline; the system contract defines the low-confidence fallback. A miss cannot be diagnosed from AP alone—you must locate the broken link.

Development of theory

Problem → Idea → Assumption → Failure → Improvement → Modern Form

Use this six-part lens for every algorithm and paper.

  1. Problem

    Images are ambiguous projections

    Many 3D scenes, materials, and lighting conditions can produce similar pixels. Vision is an inverse problem, not a lookup table.

  2. Idea

    Encode structure and invariance

    Geometry constrains rays and motion; filters expose local change; probabilistic models express uncertainty; features reduce nuisance variation.

  3. Assumption

    The world follows a useful simplification

    Brightness is locally constant, a surface is planar, motion is rigid, noise is Gaussian, labels are representative, or train and test distributions match.

  4. Failure

    Reality violates the simplification

    Specularities break brightness constancy; parallax breaks a homography; occlusion breaks matching; long tails break global averages.

  5. Improvement

    Add robustness, data, or a better state

    Use robust estimators, multiscale processing, learned representations, temporal context, sensor fusion, uncertainty, and targeted data collection.

  6. Modern form

    Hybrid systems with explicit contracts

    Foundation features and end-to-end learning coexist with calibration, geometry, filters, safety monitors, runtime constraints, and human review.

Mathematical backbone

Three equations, one reasoning habit

Write the model, inspect the residual, and test the assumptions.

Projection: observation from state

u = fxX/Z + cx
v = fyY/Z + cy

Depth appears in the denominator, so pixel sensitivity is nonlinear. A coordinate-frame mistake can look like a model failure.

Estimation: state from residuals

x* = arg minx r(x)TΣ−1r(x)

The covariance weights errors by reliability. Robust losses are needed when the assumed residual distribution cannot explain outliers.

Learning: risk on a distribution

θ* = arg minθ E(x,y)∼D[L(fθ(x), y)] + λR(θ)

The dataset distribution is part of the objective. Slice failures reveal when the empirical distribution hides the operating domain.

Worked example

How depth uncertainty moves a projected point

A calibrated camera has fx = 800 px and cx = 640 px. A point is at X = 1.5 m, Z = 12 m.

u = 800 × 1.5 / 12 + 640 = 740 px

The local sensitivity to depth is:

|∂u/∂Z| = fx|X|/Z2 = 8.33 px/m

If depth uncertainty is approximately 0.20 m, first-order pixel uncertainty is about 1.67 px. That number becomes meaningful only with its assumptions: intrinsics are fixed, X is treated as known, distortion is corrected, and linearization is valid near 12 m.

Advanced extension: now add focal-length uncertainty, correlation between X and Z, rolling shutter, and a 50 ms timestamp offset. Which term dominates for a moving object?

Mastery gate

Before moving on

  • Trace one real feature from sensor capture to product action.
  • Name the model, state, residual, uncertainty, and degeneracy at the estimation step.
  • Explain one classical method, why it failed, and which part survives in a modern method.
  • Describe how a data improvement differs from an architecture improvement.
  • State a degraded-mode behavior when fusion or runtime contracts fail.
