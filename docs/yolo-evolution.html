Deep dive · YOLO evolution

From grid regression to NMS-free real-time vision

Trace why each YOLO design appeared, separate the post-v3 lineages, and learn to choose a detector by assignment, deployment, data, and failure-mode constraints—not by version number.

Study contract

A version name is not an experiment

For every model, identify the changed mechanism, its training signal, its inference graph, and the bottleneck it targets. Then compare exported pipelines on the same data and hardware. A higher number alone proves none of those things.

01 · Naming truth

After YOLOv3, the number line branches

The first three papers form a clear author lineage. Later releases come from different research groups and repositories, often borrowing ideas from one another without forming a single governed series.

2016YOLOv1one network, one pass
2017YOLOv2anchors + multi-scale
2018YOLOv3three-scale prediction
2020Branch pointdifferent teams continue
2020–25Parallel linesv4–v13 + named work
2026YOLO26Ultralytics release name
AlwaysCompare evidencenot adjacent numbers
Original papers

Redmon / Farhadi

v1 → v2 / YOLO9000 → v3. This is the clearest direct paper lineage and establishes unified regression, anchors, and multi-scale prediction.

Darknet research line

v4 → v7 → v9

Overlapping Academia Sinica authors connect v4, Scaled-YOLOv4, YOLOR, v7, and v9 through CSP scaling, feature-flow design, reparameterization, GELAN, and PGI.

Ultralytics product line

v5 → v8 → 11 → 26

A deployment-oriented repository lineage. “YOLO11” intentionally omits the letter v; YOLO26 is its 2026 end-to-end family, not the twenty-sixth paper in one chain.

Independent releases

v6, v10, v12, v13

Meituan, Tsinghua-affiliated, and other teams publish separate systems: efficient industrial design, NMS-free dual assignment, area attention, and hypergraph feature fusion.

Missing numbers are not missing lessons. As of July 2026, no broadly recognized primary release establishes YOLOv14 or YOLOv15. Jumping from YOLO13 to YOLO26 reflects naming by different teams, not twelve undocumented upgrades.

02 · Evolution matrix

Read each release as problem → mechanism → consequence

The tables are a study index, not a universal ranking. “Dense + NMS” means many spatial predictions are decoded and duplicate boxes are removed after the network.

Foundations: v1 to v4

YOLOv1 through YOLOv4 evolution
Release Problem being attacked Important upgrade Study consequence
YOLOv1 · 2016 ↗ Region-proposal pipelines repeat computation and are difficult to run in real time. A single CNN regresses grid-cell boxes, objectness, and class probabilities as one global problem. No anchor priors. Extremely fast, but coarse cells struggle with localization, small objects, and crowded groups.
YOLOv2 / YOLO9000 · 2017 ↗ v1 recall, localization, resolution, and fixed-category limitations. Batch normalization, anchor boxes, k-means dimension clusters, direct location prediction, passthrough features, multi-scale training, and WordTree joint training. Anchors improve recall and specialization but add priors, matching choices, and duplicate predictions that still require NMS.
YOLOv3 · 2018 ↗ Single-scale prediction misses objects whose size does not match the final feature map. Darknet-53 residual backbone, three-scale FPN-style prediction, objectness, and independent logistic class scores. Strong multi-scale template, still anchor-based and NMS-dependent. Independent class logits allow multi-label predictions.
YOLOv4 · 2020 ↗ Improve the accuracy–speed frontier while remaining trainable on common GPUs. CSPDarknet53, SPP, PAN, Mish, Mosaic, CIoU, and a systematic Bag of Freebies / Bag of Specials study. Shows that architecture, augmentation, loss, and serving cost must be studied together. The detector remains anchor-based, dense, and NMS-dependent.

Parallel engineering: v5 to v10

YOLOv5 through YOLOv10 evolution
Release Problem being attacked Important upgrade Study consequence
Ultralytics YOLOv5 · 2020 ↗ Make training, transfer, export, and deployment accessible in a maintained PyTorch stack. CSP/C3-era blocks, PAN/FPN neck, SPPF, AutoAnchor, strong augmentation, model scaling, and broad export support; details evolved across repository releases. An influential repository release rather than an original version paper. Record the exact tag and weights when reproducing results.
Meituan YOLOv6 · 2022–23 ↗ Industrial throughput across model sizes and deployment engines. EfficientRep / Rep-PAN, efficient decoupled heads, distillation, anchor-free prediction with anchor-aided training; v3.0 adds BiC and SimCSPSPPF. Train-time branches can collapse into efficient deploy blocks. Exported latency matters more than raw PyTorch timing.
YOLOv7 · 2022 ↗ Preserve useful gradient paths while scaling real-time networks. E-ELAN, compound scaling for concatenation networks, planned reparameterized convolution, auxiliary heads, and trainable bags of freebies. Training graph and inference graph can differ. Fuse reparameterized blocks before measuring deployment.
Ultralytics YOLOv8 · 2023 ↗ Remove anchor-prior tuning and unify detection, segmentation, pose, classification, and OBB workflows. C2f feature blocks, decoupled anchor-free head, Task-Aligned Assignment, IoU loss plus Distribution Focal Loss. Anchor-free is not NMS-free. Dense locations still produce duplicate boxes and use NMS.
YOLOv9 · 2024 ↗ Deep networks can discard information needed to form reliable gradients. Programmable Gradient Information (PGI) and Generalized ELAN (GELAN) coordinate training supervision with efficient feature aggregation. The reversible auxiliary branch is training-only; the main branch serves at inference. Dense outputs still use NMS.
Tsinghua YOLOv10 · 2024 ↗ NMS adds latency, thresholds, and integration complexity; dense heads also contain redundant computation. Consistent dual assignments: one-to-many supervision helps training while a one-to-one branch learns unique predictions; holistic efficiency changes reduce head and backbone cost. The one-to-one branch is deployed without NMS. Benchmark the exported model because an unfused framework graph may execute branches that export removes.

Recent branches: YOLO11, v12, v13, and YOLO26

YOLO11 through YOLO26 evolution
Release Problem being attacked Important upgrade Study consequence
Ultralytics YOLO11 · 2024 ↗ Improve the efficiency and task coverage of the v8 product line. C3k2 blocks, C2PSA spatial attention, revised neck/head components, and unified task variants. Standard detection remains anchor-free, dense, DFL-based, and NMS-dependent. C3k2 is a block name—not a 2×2 convolution claim.
YOLOv12 · 2025 ↗ Use attention's receptive field without losing real-time throughput. Area Attention partitions features into simple horizontal or vertical areas; R-ELAN adds scaled residuals and stable aggregation; FlashAttention reduces memory traffic. Attention speed depends on kernels and hardware support. The published family retains dense detection and NMS.
YOLOv13 · 2025 ↗ Pairwise/local aggregation cannot directly express global many-to-many, cross-scale relations. HyperACE learns hyperedges over multi-scale pixels; FullPAD redistributes enhanced features through backbone, neck, and head; depthwise-separable blocks limit cost. An arXiv preprint with N/S/L/X variants. The official YAML ends in a standard dense Detect head, so “full pipeline” does not mean NMS-free.
Ultralytics YOLO26 · 2026 ↗ Simplify end-to-end deployment, lighten DFL-heavy heads, reduce training cost, and rescue tiny objects with zero positive candidates. Default one-to-one NMS-free head plus optional one-to-many NMS head, direct DFL-free regression, MuSGD, Progressive Loss, and STAL; task-specific segmentation, pose, and OBB changes. Two inference contracts expose a real speed–accuracy choice. Official COCO checkpoints use Objects365-v1 pretraining and tuned schedules, so compare training recipes as well as architecture.

YOLO-Master · preprint 2025 / CVPR 2026 ↗ Expert-specialized mixture-of-experts with dynamic routing for efficient specialization. Represents a current non-numbered direction: conditional computation rather than another dense block stack. Evidence that v14 or v15 exists.

03 · Prediction logic

Anchors, assignment, and duplicate removal are separate choices

Three questions define the head: how a box is parameterized, how targets are assigned during training, and how duplicate predictions are handled during inference.

1Anchor prioroffset from preset shape
2Anchor-free pointdistances from location
3Assignmentwhich outputs learn object
4Dense duplicatesmany boxes per object
5NMS or unique matchremove or prevent copies
6Output contractvariable or fixed top-k

Box parameterization

Anchor-based

Each feature location owns several prior shapes. The head predicts center offsets and width/height transforms relative to a selected prior. Good priors can specialize learning, but the number, scale, aspect ratios, matching thresholds, and dataset shift all become configuration.

x = cell_x + sigmoid(t_x) y = cell_y + sigmoid(t_y) w = prior_w × exp(t_w),   h = prior_h × exp(t_h)

Box parameterization

Anchor-free

A feature point predicts a center or distances to the four box sides. This removes the bank of preset shapes and often simplifies transfer across datasets. It does not guarantee unique predictions: nearby points may all predict the same object.

box = (x_p − l, y_p − t, x_p + r, y_p + b) location p + four learned distances → one candidate box
Assignment cardinality determines the supervision–duplication trade-off.
Choice Training signal Inference behavior Why choose it Main cost
One-to-many Several locations or anchors become positive for one ground-truth object. Dense candidates usually contain duplicates; thresholding and NMS select survivors. Rich positive supervision, strong early optimization, and often slightly higher AP. NMS latency, threshold sensitivity, variable output count, and crowded-scene suppression errors.
One-to-one One prediction is selected for each ground-truth object under a matching cost. Predictions are trained to be unique, enabling direct NMS-free decoding. Simpler end-to-end graph, stable fixed top-k contract, and lower post-processing cost. Sparser supervision can be harder to optimize and may trail a dense path in accuracy.
Dual assignment A dense one-to-many path teaches features while a one-to-one path learns the deploy contract. Deploy the one-to-one path; some families retain an optional dense path with NMS. Combines training signal with NMS-free inference. YOLOv10 and YOLO26 use related but not identical designs. Training complexity and branch-balancing choices; verify which branch the exporter actually emits.

One-to-many flow

Learn broadly, suppress later

  1. Generate candidate points or anchors across feature levels.
  2. Assign several aligned candidates to each object.
  3. Optimize class, objectness, and box losses on those positives.
  4. Decode many overlapping boxes, then apply score filtering and NMS.

One-to-one flow

Learn uniqueness before deployment

  1. Build a candidate set and a classification/localization matching cost.
  2. Select a unique prediction for each object.
  3. Teach unmatched predictions to represent no object.
  4. Decode the ranked set directly without class-wise NMS.

Critical distinction: anchor-free answers “how is a box represented?” NMS-free answers “how are duplicate boxes prevented?” A detector can be anchor-free and still need NMS, as in standard YOLOv8 and YOLO11 detection.

Localization representation

Distribution Focal Loss versus direct regression

DFL: predict a distribution

For each side of the box, the head predicts logits over discrete distance bins. Softmax gives probabilities; the expected bin becomes the decoded distance. A non-integer target supervises its two neighboring bins with linear weights.

p_i = softmax(z)_i d_hat = Σ i × p_i,   i = 0 … reg_max target y → weighted supervision at floor(y) and ceil(y)

Why use it: it represents ambiguity near boundaries and gives fine-grained localization gradients. Cost: four distributions replace four scalars, add decoding, and impose finite bin support.

Direct regression: predict a scalar

YOLO26 sets the regression design to a direct four-distance output, removing the DFL decoder and its bin channels. The paper compensates with Progressive Loss and STAL rather than claiming direct regression is free accuracy.

(l, t, r, b) = f(feature) four continuous values → decoded box

Why use it: lighter heads, unconstrained range, simpler export, and broader accelerator compatibility. Cost: less explicit distribution modeling, so the complete loss and assignment recipe matters.

Terminology check: DFL is the localization term from Generalized Focal Loss. It is not the same mechanism as the original classification Focal Loss used to address foreground–background imbalance.

04 · Efficient learning and serving

What helps only training, what changes inference, and what moves information

YOLOv4 vocabulary

Bag of Freebies

Methods that improve training or generalization without intentionally increasing the deployed model graph: data augmentation, label smoothing, better box losses, regularization, or offline data processing.

Choose when: training budget and data realism can increase but serving cost cannot. Validate: the final export really has the same operators and latency.

YOLOv4 vocabulary

Bag of Specials

Modules or post-processing that improve accuracy for a modest inference cost: receptive-field blocks, attention, feature fusion, activation choices, or NMS variants.

Choose when: measured accuracy gain justifies the runtime and integration overhead. The labels are contextual; a train-time branch that fuses away can become effectively “free” at deployment.

YOLOv9

Programmable Gradient Information is a training design

1Inputshared evidence
2Main branchfuture deploy path
3Auxiliary branchreversible information path
4Multi-level signalsusable supervision
5Program gradientsreduce information loss
6Serve main onlyauxiliary path removed

Why PGI: a lossy feed-forward path may not preserve everything a deep loss needs. PGI introduces auxiliary reversible and multi-level information paths so useful gradients reach the main network. Why not always: it complicates training and reproduction; the value must appear in an ablation while the serving graph stays unchanged.

05 · Recent mechanisms

Pairwise attention, many-to-many hypergraphs, and tiny-target assignment

These mechanisms attack different failures. They are alternatives only when the measured bottleneck overlaps.

Area Attention and HyperACE encode different relation structures.
Mechanism Relation being modeled Efficiency idea When it may be better Risk to test
YOLOv12 Area Attention Pairwise token-to-token attention inside a horizontal or vertical area. Simple reshape partitions the map into a fixed number of areas, reducing quadratic work while keeping a larger field than small local windows; FlashAttention reduces memory traffic. Context and receptive field limit a CNN baseline, and the target GPU has efficient attention kernels. Kernel availability, memory, CPU/edge slowdown, higher-resolution scaling, and convergence of large variants.
YOLOv13 HyperACE + FullPAD Learned hyperedges connect multiple spatial vertices across feature scales, supporting many-to-many high-order messages as well as a local low-order branch. Learn vertex participation, aggregate vertex→hyperedge→vertex with linear message passing, then distribute the enhanced feature through gated FullPAD tunnels. Complex scenes require cross-location and cross-scale associations that pairwise/local aggregation misses. Dataset-specific contextual shortcuts, operator/toolchain maturity, memory traffic, and latency of L/X variants.
Convolutional FPN/PAN baseline Local kernels plus hierarchical multi-scale fusion. Highly optimized standard operators and predictable memory access. Edge portability, maintainability, or dataset size matters more than richer relation modeling. Receptive field and missed contextual interactions; test against attention/hypergraph variants rather than assuming either direction wins.

YOLO26 STAL

Change the candidate mask, not the localization target

1Tiny true boxmay contain no grid center
2Detect zero coverageTAL candidate failure
3Build surrogateexpand width/height for mask only
4Select candidatesguarantee positive coverage
5Restore true boxscore and regress original
6Receive gradienttiny object is no longer dropped

Why the failure exists

Task-Aligned Assignment first masks candidate centers to those inside a ground-truth box. After feature downsampling, an object smaller than the grid spacing can contain no center. With no candidate, it contributes no classification or localization gradient.

Why STAL is conservative

STAL enlarges each too-small dimension only while constructing the candidate mask. Task-aligned scoring, final assignment, and regression still use the original box, so the detector is not trained to predict an inflated object.

STAL is not a complete small-object solution. If input resolution erases the object, labels are noisy, or the feature pyramid has no sufficiently fine level, candidate coverage cannot recover missing visual evidence. Compare higher resolution, tiling, a P2 head, data changes, and tracking alongside assignment.

YOLO26 optimization

Progressive Loss aligns training with the deployed head

Early

Favor dense signal

Weight the one-to-many branch more strongly to stabilize shared feature learning.

Middle

Transfer emphasis

Decrease the dense branch weight while increasing the one-to-one objective.

Late

Match deployment

Optimize the head that will produce NMS-free predictions at inference.

Update

Use MuSGD

Mix Muon and SGD updates for multidimensional weights; retain SGD for one-dimensional parameters.

Export

Choose a path

Use default one-to-one NMS-free output or optional one-to-many output with NMS.

06 · Selection logic

Choose a candidate by the constraint that can reject it

Start with the output contract and deployment target. Architecture novelty is a later filter.

Decision tree

  1. Must categories change at inference? If yes, test YOLOE / YOLOE-26 for text, visual, or prompt-free modes and YOLO-World for text-conditioned open vocabulary. If labels are fixed and domain-specific, continue with a closed-set detector.
  2. Must the exported graph avoid class-wise NMS? If yes, begin with YOLOv10 or the YOLO26 one-to-one path. Verify top-k support and output semantics in the target runtime. If no, dense YOLOv8, v9, YOLO11, v12, v13, or the YOLO26 NMS path remain candidates.
  3. Is the bottleneck CPU, mobile, or accelerator compatibility? Start from a small convolutional model with proven export support. YOLO26 removes DFL and NMS from its default path; YOLO11 or v8 can be simpler mature baselines. Do not assume attention is fast outside the GPU and kernel measured by its paper.
  4. Are tiny objects the dominant measured error? Compare resolution, tiling, P2 features, label quality, STAL, and temporal aggregation. Select the cheapest change that improves APS and downstream recall without unacceptable false positives.
  5. Does complex cross-object context dominate? Add YOLOv12 and v13 as controlled candidates. Area attention models pairwise relations over areas; HyperACE models learned many-to-many relations. Keep the simpler FPN/PAN baseline until an ablation shows domain benefit.
  6. Is reproducibility or ecosystem maturity the strongest constraint? Prefer a pinned, well-supported repository and export path over a newer preprint. Record code commit, weights, license, preprocessing, and post-processing before comparing metrics.

07 · Evidence

Benchmark the system that will actually run

A model table is comparable only when data, training, decoding, runtime, and measurement boundaries match.

1Freeze contracttask + thresholds + output
2Freeze datasplit + labels + slices
3Match recipepretrain + epochs + input
4Export modelssame runtime + precision
5Measure pipelinewarm-up + p50/p95/p99
6Analyze failuressize + class + conditions

Control variables

Make the comparison fair

  • Same train/validation split, label mapping, ignored regions, and leakage checks.
  • Same input size, resize/letterbox policy, normalization, and augmentation budget.
  • Disclose external pretraining, pseudo-labels, epochs, optimizer, and hyperparameter search.
  • Same device, power mode, batch, precision, runtime, workspace, dynamic/static shapes, and concurrency.
  • Export, fuse, and warm up every model; verify numerical drift before timing.
  • Include preprocessing, host/device transfer, decode, top-k, and NMS inside or outside every measurement consistently.

Report enough evidence

Reject averages without tails

  • COCO-style AP, AP50, AP75, and AP by small/medium/large objects.
  • Per-class recall, false positives per image, confidence calibration, and domain slices.
  • p50, p95, p99 latency, throughput, peak memory, model size, and energy when relevant.
  • Cold start, warm-up count, repeated runs, confidence intervals, and raw timing logs.
  • Downstream tracking, temporal stability, or safety metrics if boxes feed another system.
  • Qualitative failures with a hypothesis and a discriminating next experiment.

Three comparison traps: (1) YOLOv10 should be timed after export because unused training branches can distort framework latency. (2) YOLO26's reported COCO checkpoints use Objects365-v1 pretraining and model-size-specific tuning, unlike many train-from-scratch tables. (3) YOLO26's one-to-one and one-to-many paths trade NMS-free simplicity against a typical accuracy advantage for the dense path; report which path was measured.

08 · Retrieval and application

Misconceptions, MCQs, and coding practice

Quick misconception repair.
ClaimCorrectionFast verification
“YOLOv13 must follow YOLO12's code.”Numbers span independent teams and repositories.Read author lists, repository ownership, model YAML, and citations.
“Anchor-free means no post-processing.”Dense anchor-free heads can produce duplicates and require NMS.Inspect exported outputs and the prediction pipeline.
“End-to-end in a title means NMS-free.”The term can describe training or pipeline scope; it does not prove unique output assignment.Check the head, assignment cardinality, and whether inference calls NMS.
“More FLOPs always means slower.”Kernel efficiency, memory movement, fusion, precision, and hardware dominate wall-clock behavior.Benchmark the exported engine on the target device.
“The newest checkpoint is a fair architecture comparison.”Pretraining, augmentation, tuning, and data can move AP independently of architecture.Run controlled training or disclose the recipe difference.
MCQ 1 · Which change is sufficient by itself to make a detector NMS-free?
  1. Replace anchors with points.
  2. Use DFL for box distances.
  3. Train predictions with a uniqueness-preserving one-to-one assignment and direct decode contract.
  4. Add a finer feature level.

Answer: C. Anchor-free changes box parameterization, not duplicate behavior. One-to-one set-style supervision is the relevant mechanism.

MCQ 2 · Why keep a one-to-many branch during dual-head training?
  1. It provides richer positive supervision.
  2. It guarantees lower serving latency.
  3. It removes all matching costs.
  4. It eliminates the classifier.

Answer: A. Dense positives stabilize feature learning. The branch may be discarded or made optional at deployment.

MCQ 3 · What does DFL decode for one box side?
  1. The argmax class label.
  2. The expected value of a probability distribution over distance bins.
  3. An anchor aspect ratio from k-means.
  4. An NMS threshold.

Answer: B. Neighboring bins also provide interpolation-like supervision for non-integer targets.

MCQ 4 · Which YOLOv9 component must remain at inference for PGI to help?
  1. The reversible auxiliary branch.
  2. Every auxiliary head.
  3. Only the trained main branch.
  4. A language encoder.

Answer: C. PGI shapes training gradients; the auxiliary reversible path is not required in the serving graph.

MCQ 5 · What does YOLO26 STAL enlarge?
  1. The regression target box.
  2. The image at inference.
  3. Only the surrogate geometry used to build the candidate-selection mask.
  4. Every predicted box before NMS.

Answer: C. Scoring, final assignment, and regression retain the original target box.

MCQ 6 · What is the strongest evidence that YOLOv12 is faster for a target system?
  1. Its attention complexity formula.
  2. Its paper's result on another GPU.
  3. Its parameter count.
  4. Repeated exported-pipeline latency on the target hardware and precision.

Answer: D. Area Attention and FlashAttention gains depend on operators, kernels, memory, shape, and hardware.

Coding practice

Build mechanisms before benchmarking whole repositories

Lab 01 · Geometry

IoU and class-wise NMS

Implement vectorized IoU and NMS. Test empty input, identical boxes, ties, class separation, numerical stability, and quadratic scaling.

Lab 02 · Parameterization

Anchors versus points

Fit k-means anchor dimensions, implement anchor decode and l/t/r/b point decode, then compare coverage under a shifted aspect-ratio distribution.

Lab 03 · Localization

DFL encode and decode

Encode fractional distances into adjacent bins, decode by expectation, check gradients, then compare output channels and range with direct regression.

Lab 04 · Assignment

TAL zero-candidate case

Create a tiny box between grid centers. Reproduce zero coverage, add an STAL-style candidate surrogate, and assert that regression still uses the true box.

Lab 05 · Dual heads

Progressive branch loss

Train a toy dense and unique-prediction head. Plot positive counts, branch gradients, and a linear shift from dense to one-to-one supervision.

Lab 06 · Deployment

Fuse reparameterized blocks

Fold batch normalization and sum 3×3, padded 1×1, and identity kernels. Assert maximum output error before timing both graphs.

Lab 07 · Context

Area versus hyperedge messages

Implement striped pairwise attention and vertex→hyperedge→vertex aggregation on a small tensor. Compare relation structure, memory, and scaling.

Lab 08 · Evidence

Export benchmark harness

Report warm-up, p50/p95/p99, memory, AP by size, preprocessing, decode, and NMS. Save environment and raw samples with the result.
