Model the sensor before trusting the model

Camera and multi-sensor calibration

Calibration connects pixels to rays, rays to metric frames, and asynchronous sensors to one physical event. Learn the equations, the estimation workflow, and the production checks that prevent a small geometric error from becoming a large BEV or tracking failure.

Core theory

From a world point to a pixel

Use the convention T_camera_world: it maps a homogeneous point from the world frame into the camera frame.

Pc = R Pw + t = [X, Y, Z]T x = X / Z,   y = Y / Z [u, v, 1]T ∼ K [x, y, 1]T K = [[fx, s, cx], [0, fy, cy], [0, 0, 1]]

Checks before projection: units agree; the frame direction is correct; Z > 0 under the chosen camera convention; the calibration version matches the image; and the timestamp is meaningful for a moving rig.

Worked example

Compute before coding

Let fx = fy = 800 px, principal point (640, 360), zero skew/distortion, and camera-frame point (0.5, 0.2, 10) m.

  1. Normalize: x = 0.5/10 = 0.05, y = 0.2/10 = 0.02.
  2. Scale and offset: u = 800·0.05 + 640 = 680.
  3. v = 800·0.02 + 360 = 376.

The pixel is (680, 376). Doubling every 3D coordinate leaves the pixel unchanged; doubling only depth moves it toward the principal point.

Lens model

Distortion lives in normalized coordinates

Model only the complexity your observations constrain. A flexible model can fit calibration-board noise and still generalize badly.

For r² = x² + y², a common radial-plus-tangential model is:

xradial = x(1 + k₁r² + k₂r⁴ + k₃r⁶) yradial = y(1 + k₁r² + k₂r⁴ + k₃r⁶) x′ = xradial + 2p₁xy + p₂(r² + 2x²) y′ = yradial + p₁(r² + 2y²) + 2p₂xy

Then apply K to (x′, y′). Fisheye and omnidirectional cameras require models suited to their field of view; coefficient names and signs are library-specific contracts, not universal facts.

Estimation workflow

Collect observations that excite the model

  1. Specify: frames, units, image size, lens model, focus/exposure state, temperature/rig conditions.
  2. Capture: board or scene features across image corners, depth, roll, pitch, and yaw—not only centered frontoparallel views.
  3. Initialize: estimate per-view pose and camera parameters using a linear or planar method.
  4. Refine: minimize robust reprojection error over intrinsics, distortion, and poses.
  5. Validate: held-out views, residual maps, physical plausibility, and downstream metric geometry.
  6. Package: immutable calibration ID, validity conditions, covariance/quality, source observations, and compatible software schema.

Degeneracy watch

Low loss does not prove identifiability

  • Centered frontoparallel boards correlate focal length, distance, and distortion.
  • A tiny image footprint cannot constrain edge distortion.
  • Pure rotation or poor scene depth can weaken translation/scale estimation.
  • Weak camera-LiDAR overlap makes an apparently stable extrinsic misleading.
  • Constant-velocity motion can correlate clock offset with translation.
  • Optimizing too many coefficients can fit noise and target imperfections.

Dynamic and online calibration

Monitor continuously; update only when the geometry is observable

A moving rig needs a trusted offline baseline, independent health signals, and a bounded correction policy—not an unconstrained six-degree-of-freedom optimizer on every frame.

1Baselinetarget-based nominal
2Monitortime + residual health
3Gatemotion/scene observability
4Refinebounded spatial/time delta
5Validateheld-out/downstream checks
6Commitaccept, freeze, or rollback

Separate the operating modes

  • Offline target calibration: establish intrinsics, rigid extrinsics, clock convention, covariance, and a versioned nominal state under controlled coverage.
  • Online health monitoring: watch reprojection/edge residuals, timestamp innovations, overlap coverage, temperature/flex indicators, and downstream BEV disagreement without changing parameters.
  • Bounded online refinement: estimate a small correction only after excitation and cross-modal agreement pass an observability gate.
  • Joint spatiotemporal calibration: estimate extrinsic correction and clock offset together when motion makes them distinguishable; otherwise hold one fixed.

Use a nominal-plus-correction model

Tcamera←lidar(t) = Exp(δξ(t)∧) Tcamera←lidar,0 (δξ*, Δt*) = arg min Σ ρ(rk(δξ, Δt)) + ‖δξ‖²Σ⁻¹

Constrain correction magnitude/rate and require diverse static geometry, sufficient translation/rotation, valid overlap, and enough depth. Dynamic actors, flat-road-only scenes, constant motion, modality-specific edges, and correlated time/extrinsic error can make a low loss misleading.

State machine: healthy → suspect → shadow refinement → validated update. If observability or held-out checks fail, freeze the last-known-good parameters; if downstream metrics regress, rollback the calibration version and retain the evidence for offline diagnosis.

See the autonomous-driving learning flow for the downstream chain from synchronized sensors and calibration through localization, BEV/occupancy, prediction, planning, and control.

Validation

Read the shape of residuals

Radial edge pattern

Suspect distortion model/coefficients, weak edge coverage, wrong resize, or a calibration from a different focus/resolution.

Nearly uniform vector offset

Suspect principal point, crop/ROI, frame translation, or timestamp error under motion.

Residual grows with range

Check small rotation error, focal scale, baseline, timing, and the metric ground-truth process.

Only moving objects disagree

Check sensor capture times, rolling shutter, deskew, per-object motion, and interpolation—not only rigid extrinsics.

One camera/view is bad

Inspect feature detection, blur, flex, exposure, target visibility, and whether that observation should be downweighted or rejected.

Mean is good; BEV is unstable

Inspect per-region/per-view percentiles, calibration sensitivity, coordinate conventions, and temporal version mismatch.

Applied lab

Build a calibration auditor

Open coding exercises
  1. Generate a synthetic camera, planar board poses, distortion, and noisy corner observations.
  2. Estimate or load intrinsics/extrinsics and compute per-point residual vectors.
  3. Inject focal, principal-point, radial, pose, resize, and timestamp faults one at a time.
  4. Report mean, median, p95/max, per-view values, image-coverage heatmap, radial trend, and held-out error.
  5. Project independent 3D landmarks or LiDAR points and decide whether the calibration is fit for the intended BEV range.

Gate: diagnose at least four injected faults, reject a degenerate capture, preserve all frame/unit/time conventions in code, and write a recalibration/rollback policy.

System review prompt

A rig is correct in the lab and drifts after 30 minutes of driving

Design the investigation. Separate thermal/mechanical flex, clock drift, rolling shutter, changing focus, data-version mismatch, and estimator error. Specify observability, monitors, safe fallback, recalibration trigger, ownership, and the experiment that distinguishes the leading hypotheses.
