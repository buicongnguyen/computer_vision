Reasoning rule

A plausible answer is not yet a supported answer

Begin with the requested output and its contract. Check frame, time, units, observability, validity, uncertainty, causal mechanism, and safety before comparing algorithms. Then name the experiment that could prove the choice wrong.

Flow of thinking

Turn every answer into a falsifiable engineering claim

The loop returns to assumptions when evidence does not match the predicted mechanism.

Flow of data

The payload plane and the trust plane must travel together

“Latest message from each sensor” is not a synchronization policy: it can combine observations of different physical scenes.

Flow of code

Make frame, time and validity part of the type contract

Ambiguous arrays make geometry bugs global. Typed stages localize the first violated invariant.

Language-neutral pseudocode

def build_world_state(bundle: SensorBundle,
                       tf: TransformSnapshot,
                       pose: PoseSpline,
                       t_ref: Time) -> WorldState | TypedError:
    checked = validate_contract(bundle, t_ref)
    if checked.is_error: return checked.error
    aligned = align_and_deskew(checked.value, tf, pose, t_ref)
    if aligned.is_error: return aligned.error
    features = run_frontends(aligned.value)
    if features.is_error: return features.error
    state = fuse_and_update(features.value, t_ref)
    return validate_world_state(state)

is_error and .value make failure propagation explicit; they are pseudocode, not a Python or Rust library. Each helper has a smaller contract, a scalar/synthetic oracle, and a typed failure path. Logging includes model, calibration, transform and scenario versions.

Six trace prompts to practice

  1. LiDAR cloud: packet → validated returns → Cartesian points.
  2. Deskew: point times + pose spline → one reference time.
  3. ICP: correspondences → robust normal equations → pose or degeneracy.
  4. RGB–LiDAR: aligned points → projection → depth-buffered overlay.
  5. Collision: trajectory + occupancy → contact/clearance trace.
  6. Closed loop: observe → act → advance → score → replay.

For each prompt, draw the input contract, stage sequence, rejection paths, expected residual and regression evidence before coding. Open the autonomy coding exercises →

Causal debugging

Diagnose the shape of the residual before changing parameters

A cause is credible when it predicts error direction and magnitude, not when random tuning improves one image.

Answer correctly

Use one causal structure for derivations, MCQs and system questions

  1. Assumptions: name the ODD, available sensors, motion, geometry and timing conditions.
  2. Contract: state the output, frame, timestamp, units, validity and uncertainty.
  3. Choices: list only methods compatible with observability and resource constraints.
  4. Selection: choose conditionally and explain the causal mechanism.
  5. Nearest alternative: state when it becomes better and why it is not preferred here.
  6. Failure mode: predict the residual or behavioral symptom when the assumption breaks.
  7. Detection and fallback: name the monitor, guard and safe response.
  8. Verification: match the experiment and metric to the scope of the claim.

Avoid absolute answers

“Best,” “end-to-end,” and “multimodal” are incomplete without a boundary

A strong answer states what is jointly learned, which inputs and outputs are declared, which invariants remain external, which faults are covered, and what evidence would justify the claim.

Scenario regression flow

requirement / ODD → scenario family → parameter ranges → concrete test → replay/simulation → assertions → failure cluster → minimized case → permanent regression

Store the initial state, actors, trigger, expected safe behavior, hard assertions, soft KPIs, fault, seed, and software/model/calibration versions.
